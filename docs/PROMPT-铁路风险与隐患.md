# 铁路风险与隐患数字站场改造提示词

版本：2026-11-15。用途：替换现有数字工厂题材，指导铁路危货风险与隐患场景、不同地区货运站台及专项推演页面的设计和开发。本文是实施提示词，**不是已完成的功能说明**。

现有演示的提炼归档见 [数字工厂提示词提炼.md](./数字工厂提示词提炼.md)。需求依据与逐页对应关系见文末。以下“主提示词”和“地区提示词”可直接交给设计或开发代理使用。

## 一、主提示词

你正在改造现有“铁路危险货物运输‘双重预防机制’一体化信息平台”。现有 React 平台已接入一个 three.js 数字工厂视觉演示。请将演示的题材、空间模型、指标、标签和交互，整体改造为“铁路危险货物运输风险与隐患数字站场”。

### 1. 项目目标

让用户明确知道：当前查看哪个地区、哪个铁路局、哪个站场、哪个货运站台或作业点；这里有哪些评估风险、哪些已发现隐患，依据是什么；哪些事项待整改、待复核或逾期；若进入爆炸火灾专项，使用了哪些情景与参数、得到什么经校核的后果结果。

用真实的铁路危货作业空间和可追溯业务信息体现技术能力。三维场景服务于风险定位、证据查看和演练，不堆放与安全任务无关的仪表和装饰。

这里的“站台”以危险货物运输相关的货运装卸站台、罐车装卸栈台和站场作业区域为主。根据办理货类展示适用设施；不要把旅客站台、高铁候车站房作为危货装卸场景。站台号、股道号、装卸位号分别建档，不能互相替代。

### 2. 先核对现有项目

- 沿用 React + TypeScript + Vite 主平台和现有 three.js 场景，不无故替换技术栈。
- 先读取仓库规则、Git 状态、现有业务接口和源码；保留用户已有改动。
- 当前场景源码为 `daima/src-df/`，构建入口为 `daima/build-df.js`，平台接入为 `daima/src/SimulationSwitch.tsx`。
- `digital-factory-3d.html` 是生成产物；在源码修改后构建，不在内联 three.js 产物中手工替换。
- 复用 `daima/src/railwayScope.ts` 的局站选择契约、既有评估和隐患治理接口。该文件里的局站及统计包含演示内容，不能当成真实危货办理资质、真实地理档案或事故历史。
- 检查 `daima/src/hazardCatalog.ts` 中“进场、装卸、搬运”和“人、物、环、管”的现有分类。既有法规文本只作项目资料，正式标准的时效与适用性需另行核实，不能自行补造条款和阈值。

### 3. 业务边界：必须遵守

1. **风险、隐患和专项后果分别展示。** 风险表示可能发生的事故及后果；隐患表示已经发现并确认的具体问题；专项后果表示给定假设下的火灾或爆炸计算结果。
2. 风险分级与隐患治理仍在原系统进行。专项页不生成隐患、不处理整改闭环，仅将业务推演资料关联回原风险评估任务。
3. AI 提供解释、待核实线索和建议，不修改原有风险等级，不代替专业确认、测量或公式计算。
4. 不能因为地区气候、设备离线、一个红色模型或一次演练，就自动生成正式隐患或提高风险等级。
5. 已闭环隐患保留历史，退出当前待办统计；风险档案及其原评估等级按原业务规则保留。闭环不自动等于风险消失。
6. 示范数据、待核实线索、正式业务记录和专项演练必须能明确区分；无数据、未采集和数值零不能混用。
7. 每个按钮有真实行为。尚未接入的计算、导出、上传和回写应给出明确状态，不显示虚假的“计算完成”“已保存”或“已回写”。

### 4. 多地区、多站场、多站台

建立“地区模板 → 铁路局 → 站场/区段 → 站台/栈台/作业点”的导航。地区模板只描述环境和建模差异，不改变既有铁路局归属；模板与实际站点的关联由业务档案决定。

先提供东北、华北、华东、华南、西南、西北六类示范站场。地区代表性环境是建模素材，不是对当地实际天气、场站风险或危货办理范围的事实判断。华中及青藏高原可按相同配置方式扩展。

每类示范场景至少体现可见的站内空间差异和对应的环境参数；按适用货类配置两类以上可选择作业点，例如液体危货罐车装卸栈台、包装危货货运站台、罐式集装箱交接区。仅支持某类货物的真实站点不得为了展示补出其他资质或设施。

更换站点时，应同时更新场景模型或图片、站台列表、参数档案、风险点、隐患列表、统计、详情和巡游路线；清除上一站悬浮卡和选中对象。异步切换时取消或忽略旧响应，不能发生“标题已换站、数据还是上一站”。空站点显示清晰的未建档状态。

未获得真实站场资料时使用“东北示范货运站”等名称，显示“示范场景 / 非实测布局”。不要为真实站点编造精确坐标、股道配置、人口密度、危货办理许可或安全距离。

### 5. 铁路场景构成

用模块化铁路构件搭建可复用站场，并让各地区有实际可辨的布局差异。根据站场类型选用以下区域：

- 进场检查区：门禁、货物与单证核对、包装与标识检查、待检位置。
- 到发与调车区：钢轨、轨枕、道岔、信号设施、货运车辆、调车边界和防溜设施。
- 罐车装卸栈台：罐车、栈桥、装卸臂或管线、防静电接地、检测报警、防渗与事故收集设施。
- 包装危货货运站台：货运站台、货棚、分区货位、适用搬运设备、警示和作业边界。
- 暂存与交接区：按货物适配关系设置的暂存位、交接检查点和隔离边界。
- 应急保障区：消防车道、应急器材、应急集合点、调度值守及周边敏感目标。

股道保持连续，车辆轮对落在钢轨上；装卸设备对准作业位，人员和搬运路线可理解。不能出现轨道穿楼、车体互相穿透、列车随意漂移或所有危险货物混放。

接触网、危货装卸、停电隔离和车辆防护按场站资料及作业制度表达；缺少资料时采用明确的示意配置，不把概念模型写成安全设计结论。三维模型不得凭视觉“通过”替代安全距离校核。

保留拖动环绕、滚轮缩放、点击拾取、平滑聚焦、复位、标签、图层、自动巡游、全屏、纯净录屏和 Esc 返回。列车及人员动画只能表达演示运行；不驱动正式统计或改变隐患状态。切站、关闭场景和页面后台时管理动画与资源生命周期。

动态效果：列车沿独立通行股道经过，机车牵引货车，轮对随行程旋转，避免占用装卸作业位；循环复位应发生在可见站场之外。安排四名戴安全帽、穿反光服的安全人员沿站台与人行通道巡检，具备迈步摆臂、驻点查看、转身返回动作，路线避开股道及设施。提供统一暂停/继续和 1× / 2× / 4× 速度控制；六地区均适用，明确显示“动态演示”，不生成正式巡检记录。

### 6. 页面信息结构

**顶部：范围与来源。** 显示平台名称、当前地区/铁路局/站场/站台、时间范围、数据来源和更新时间。地区选择与站台选择保持键盘可用。

**左侧：风险管控。** 展示重大、较大、一般、低四级评估风险，按红、橙、黄、蓝及文字区分；展示风险来源、所属作业环节、管控措施和责任岗位。每项统计可以下钻到同一筛选范围内的清单。色块不是风险判定依据，避免只依赖颜色。

**中央：站场工作区。** 三维、站场平面示意、现场图片按已有资料选择。站台/栈台、股道、货物、检测点、既有隐患与敏感目标有清晰标识。点击风险点显示风险依据，点击隐患点显示记录和证据。照片未标定时仅展示人工标注位置，不生成真实米制影响范围。

**右侧：隐患治理。** 展示当前未闭环隐患、逾期项、待复核项、闭环率。单项包含编号、位置、描述、证据照片、检测值/标准、责任人、期限和治理阶段。涉及正式办理的动作跳转原流程并校验账号权限，不能在三维页另建一套闭环。

**底部：记录与工具。** 展示与当前筛选一致的巡检、评估和隐患治理记录；演示动画事件单独标记。提供视角、图层、巡游、帮助和返回工具。

删除工厂的冲压、焊装、涂装、总装、整车产量、OEE、WIP、AGV 在线率等残留文案和模型。示范统计应固定可复现、内部一致，不按随机数不断制造“实时”隐患。

### 7. 风险点、隐患点与详情

风险点至少包含：ID、所属局站和作业点、作业环节、危险因素、可能事故、已有风险等级及判定来源、现行管控措施、责任岗位、证据来源和更新时间。

隐患点至少包含：ID、关联评估/风险 ID、位置、具体问题、照片和检测记录、原标准、发现时间、责任人、整改期限、当前阶段、版本及历史入口。按现有契约保存字段，不能为实现提示词破坏旧数据。

地区差异对应的是候选关注项。例如“东北低温条件下需核查阀门密封和排水结冰”是检查建议；只有具备现场证据和适用判据的“某栈台阀门实际渗漏”才可能成为确认隐患。

隐患阶段沿用当前系统：待整改 → 整改中 → 待复核 → 复核中 → 待项目经理确认 → 已闭环。保留既有办理人、复核人、照片、检测值、退回、撤回和版本控制，不因视觉改造简化权限或越级流转。

### 8. 场站环境参数与图片

用户可以手动填写，也可以导入模板；导入须经历解析、校验、预览和确认保存，并定位行列错误。模板字段至少涵盖：

| 分组 | 字段 |
| --- | --- |
| 范围 | 地区模板、铁路局、场站/线路、站台/栈台/股道/作业点编号、区段起止里程（适用时） |
| 空间 | 布局文件、坐标系、比例尺/标定状态、设施与周边目标的位置 |
| 地形与环境 | 地形类别、坡度、桥隧/边坡/河流情况、周边城镇及敏感目标；人口数据需范围、年份和来源 |
| 气象 | 温度、风速、风向、降水等；注明实测、历史资料或演练假设，区分单位及气象风向约定 |
| 货物与作业 | 品名、适用的 UN 编号、货物物性来源、数量及单位、包装/罐型、进场/装卸/搬运等作业类型 |
| 设施与证据 | 消防、报警、防渗与应急资源资料，现场照片、检查记录、采集时间和核实状态 |
| 追溯 | 来源、填报人、确认人、档案版本、演练标记 |

缺失信息保留未知并提示采集，不能把缺失填成零。照片和参数按站点及版本关联；用户切站不能复用上一站照片冒充现场。支持上传平面图、航拍图或现场图并人工标注；普通照片不能推断不可见气体浓度、真实距离、周边人口或设施合格性。

不要为所有地方定制完整三维模型。以通用构件和地区模板覆盖典型站场；缺少三维资料时使用图片/平面图，并保持风险与隐患信息的同一套关联。

### 9. 爆炸火灾专项：独立工作区

平台风险与隐患驾驶舱可以展示专项入口，但专项内部按需求 PDF 的职责组织，不能把驾驶舱的整改操作直接搬入专项页。

两种模式：

- 业务模式：从原风险评估进入，带入已授权的任务、危货、局站和资料，明确显示关联任务；允许核对参数，保存每次推演输入快照。回写仅关联推演资料与报告，不覆盖原评估等级、不推进整改阶段。
- 模拟演练：独立创建情景，不绑定风险评估任务；保存至演练台账，不混入正式隐患统计。

顶部统计专项分析总次数、爆炸/火灾情景数、高后果推演记录，并保留局站和时间筛选。流程为“带入基础数据 → 设置泄漏情景 → 配置物性与环境参数 → 计算 → 可视化 → 生成报告”。

输出在计算成功后展示，至少分为“计算结果”和“综合报告”。按所选模型分别展示热辐射、爆炸超压、人员/设备阈值影响范围和专项后果等级。图层、图例、单位、阈值、计算版本和适用范围完整；超压和热辐射不能共用一套无单位色标。

公式和模型必须有可核查来源、适用条件、单位以及校核算例。模型不适用于当前情景或缺少必要参数时拒绝计算并列出原因。没有模型时只允许清楚标记的示意图，不绘制随意半径作为计算结果。动态烟火、波纹和环形动画只是视觉效果，不能冒充流体或爆炸物理求解。

台账包含关联任务（或独立演练标识）、场站、危货、情景、输入快照、模型版本、结果、报告和创建时间，支持查看、重算和导出 PDF。重算产生新版本并保留旧结果；失败不覆盖上一次有效记录。业务回写须校验权限、任务绑定及版本，具有失败提示和重复提交保护。

历史统计聚合真实推演记录，显示高后果危货、情景占比和场站分布。管理员可编辑场站防控规划，其他角色只读；后端执行权限校验。提供危货物性查询与 AI 提问入口，注明建议来源和限制。

### 10. 综合报告

报告至少包含：对象与范围、地区/局站/作业点、数据时间和版本、环境和货物参数及来源、现场图片与标注、既有风险及依据、现有隐患和原治理状态、管控建议、应急建议、缺失信息和复核记录。专项报告额外包含模式、绑定任务、情景、模型、输入单位、阈值、计算结果、影响图和适用范围。

允许人工编辑专项措施与建议并留存编辑记录。AI 只根据提供的记录和计算输出起草文字；将已知事实、演练假设、待核实项和建议分开表述。不要从照片编造参数，不擅自改级，不把建议称作已落实措施。导出内容与页面同一版本一致。

### 11. 视觉与性能

沿用现有场景中成熟的相机、灯光、材质、标签、图层和录屏能力。统一铁路安全主题，用真实铁路构件、清晰层级与局部风险标识表达科技感。颜色和运动不能遮盖证据与业务数据。

保持轨道、站台、车辆与周边地形的比例关系；文字可读，标签防遮挡；风险区域有文字及图例。移动端能折叠侧栏，筛选、详情、退出和触控仍可操作。支持低画质和减少动态效果。

使用实例化与资源复用，切站释放不用的几何、材质、纹理和事件监听；限制像素比、阴影成本和更新频率。后台暂停。声明离线范围：程序化场景可离线，在线地图、上传、接口和报告服务不能无依据宣称离线可用。

### 12. 分阶段交付与验收

第一阶段完成铁路场景替换与六地区切换，接入风险/隐患只读展示和原页面跳转；演示数据明确标记。第二阶段接入真实档案、图片、环境参数和报告。专项真实计算及业务回写作为需要模型与接口证据的后续阶段，不把视觉原型说成完整仿真系统。

每次交付说明实际改动、构建与验证结果、尚未实现内容。至少核对：

1. 六地区可以选择，站场布局、地形/环境表达、作业点和检查关注项有实际差别。
2. 从站点 A 切至 B 后，标题、站台、参数、模型/图片、风险与隐患、统计、详情和巡游一致；快速切换不会被 A 的迟到响应覆盖。
3. 同一站场可选不同站台/栈台/作业点，关联记录和聚焦位置正确，返回能恢复原业务上下文。
4. 铁路模型与指标完成替换，不残留工厂生产线、汽车产量和 OEE 等无关内容。
5. 风险与隐患各自统计、各自有依据；隐患已闭环不导致风险档案自动删除或降级。
6. 风险和隐患分别有正常、空数据、未知、加载中、失败、无权限和历史记录状态。
7. 图片与导入按站点绑定，缺参、无效单位和未标定场景不会产生虚假距离或计算结果。
8. 专项不创建隐患、不操作闭环；业务模式正确绑定原任务，演练不绑定；AI 不改原风险等级。
9. 已实现的计算、重算、导出和回写有真实结果、版本及失败处理；未实现项明确标识。
10. 相机控制、拾取、巡游、录屏、全屏、Esc、关闭释放和移动布局可用；运行相应构建、静态检查和浏览器验证，区分本地验证与业务验收。

## 二、六地区追加提示词

以下段落与主提示词一起使用。所有地区描述均为示范模板；实时天气、实际风险等级、办理货类和设施配置以用户确认档案为准。隐患例子是用于演示的候选样例，只有业务证据确认后才能作为正式隐患。

### NE / 东北：寒地平原货运站场

生成“东北示范货运站”。场景采用平原展开的长股道、寒地风貌、带防雨雪棚的包装危货站台，以及罐车装卸栈台。可在冬季演练中展示积雪边缘与除雪通道，工作面和轨道仍清晰可见。区分包装货物站台与液体危货作业位，不把雪景覆盖到所有设施上。

环境档案开放低温、降雪、风和冻融相关输入。风险检查关注低温下阀门/软管适用性、防滑、消防供水防冻、防溜和疏散路径；演示隐患可选“某排水口实际结冰堵塞，附照片、时间和检查依据”。寒冷背景本身不自动形成隐患。

巡游：进场核验 → 包装危货站台 → 罐车栈台 → 消防保障 → 站场总览。

### NC / 华北：城市边缘平原枢纽

生成“华北示范货运站”。采用较宽的到发/调车区域、多条平行股道、明确的站内道路与货运装卸站台。站外可设置抽象城镇建筑作为敏感目标示意，不能标注未经核实的真实距离与人口。与东北模板相比，重点体现站内交通组织和周边目标关系。

环境档案开放季节温度、风、周边敏感目标和站内交通组织信息。检查关注调车与装卸交叉作业、防溜、防静电、警戒与消防通道；演示隐患可选“指定消防通道被临时堆物占用，位置、证据和期限完整”。不能把“城镇较密集”直接换算为重大风险。

巡游：到发区 → 调车边界 → 装卸站台 → 消防通道 → 周边敏感目标。

### EC / 华东：临港联运与水网站场

生成“华东示范货运站”。用铁路装卸站台、罐式集装箱交接位及联运道路形成可读布局；场外设置示意水体与临港设施，沿作业区表达防渗地面、排水与事故收集路径。港机和堆场按货类适配，不把普通集装箱堆叠当成全部危货存储方式。

环境档案开放降水、风、排水能力、水体和周边目标资料。检查关注雨污与事故排水控制、装卸连接、雷雨/大风条件下的作业管理、罐式集装箱标识及隔离；演示隐患可选“某事故收集沟存在实测堵塞，关联检查记录”。水体位置和影响范围未核实则只作示意。

巡游：铁路接入 → 罐式集装箱交接 → 货运站台 → 排水/事故收集 → 临港环境。

### SC / 华南：湿热多雨货运站场

生成“华南示范货运站”。体现湿热多雨环境下的装卸雨棚、通风货棚、排水沟和较多绿化，保留清晰的铁路轨道与危货货位。通过排水组织和站台遮雨构造区别于其他地区，而不是只改变天空和植被。

环境档案开放温度、湿度、降水、雷电与大风相关的已确认资料或演练假设。检查关注防雷防静电、通风降温、场地防滑、雨水倒灌、消防和应急通道；演示隐患可选“已确认某搬运通道积水且防滑设施缺失，附现场证据”。不在无数据时显示实时台风预警。

巡游：雨棚站台 → 通风与监测 → 场地排水 → 罐车作业点 → 应急集合点。

### SW / 西南：山地谷地站场

生成“西南示范货运站”。采用沿谷地延伸、空间受约束的站场布局，远景表达山体、边坡、桥隧接入等元素，站台作业面保持平整且线路走向合理。边坡与作业区、防护设施、消防道路关系清楚；不让整座站场简单倾斜来代表山区。

环境档案开放地形、坡度、桥隧、边坡、降雨和应急通行资料。检查关注边坡/落石信息核查、暴雨排水、有限通道、疏散及适用情景下的通风条件；演示隐患可选“检查确认某侧沟堵塞，附位置与照片”。地质灾害与有毒气体扩散需要专业数据或模型，不能由山地外观推断。

巡游：桥隧接入示意 → 到发作业 → 谷地装卸站台 → 边坡排水 → 应急路线。

### NW / 西北：干旱开阔铁路物流站场

生成“西北示范货运站”。采用开阔、较长股道与相对低密度布局，背景为干旱地貌，表达防风沙构造、罐车栈台、包装货物站台和应急资源点。保持真实可理解的道路与货物交接，不用满屏飞沙遮挡作业区。

环境档案开放风沙、温差、日照、消防水源及救援资源资料。检查关注防风固定、标识可见性、设备密封、防静电、适用货物的温度条件、消防与救援资源可达性；演示隐患可选“检查确认某应急器材缺失或标识被遮挡，记录具体位置与依据”。不能仅凭偏远背景假设救援一定不可达。

巡游：长股道到发 → 防风沙边界 → 罐车栈台 → 包装危货站台 → 消防与救援资源。
