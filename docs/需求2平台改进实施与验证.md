## 1. 本轮实现

原顶部“铁路数字站场”现进入“铁路情景工作区”，提供三个步骤：数据与场景配置、过程与后果演示、参数与评估资料。“浏览六地区站场”继续保留原铁路场景及其列车、巡检、巡游、参数、简报和纯净录屏功能。

| 需求 | 实际改动 |
| --- | --- |
| 保留原平台业务 | 风险评估、历史、隐患与整改页面保留；现有整改状态、后端权限和双人确认规则未改动 |
| 从平台记录带入数据 | 在可访问评估记录的列表增加“情景演示”，带入编号、版本、局站、货物、问题、依据、检测结果、原等级、治理状态、措施和照片的快照；顶部入口也可选择记录 |
| 原因与假设区分 | 原因默认“待核实 / 演练假设”；勾选已确认原因后，须填写原因和证据依据 |
| 模板映射 | 六地区可选；支持罐车连接部位、包装货位、暂存交接容器三个对象，必须人工确认映射后应用。模板不是实际站场测绘 |
| 过程与结果 | 泄漏、火灾、爆炸三种定性情景，具有作业背景、问题定位、过程演示、后果与整改四阶段；通过标记、烟团、火焰、闪光表现不同过程 |
| 演示控制 | 独立的 24 秒时间轴、阶段跳转、播放、暂停、重播、1×/2×/4×；到终点停止，重新播放从起点开始。与浏览站场时的列车/巡检控制分开 |
| 图片与标注 | 上传 JPG/PNG/WebP，复用原图片压缩方式；点击照片或用键盘标注，支持说明与归一化坐标调整，配置恢复后保留。没有调用图片 AI 服务 |
| 配置留存 | 按账号保存到当前浏览器会话，支持显式保存、恢复预览、确认载入，以及 JSON 配置导入导出。更换模板对象或恢复配置后须重新确认映射 |
| 资料导出 | 导出原生 `.docx` 与 `.xlsx`，不以 HTML 改扩展名；包含参数、评估快照、模板、问题与原因、过程阶段、措施、来源及边界。Word 可嵌入证据图片，标注位置与说明同时作为文字记录；Excel 包含参数评估和过程说明两个工作表 |
| 返回业务上下文 | 已绑定且仍可访问的来源记录可从演示/资料页返回，在历史评估中打开该记录报告；普通退出保留原页面状态 |

独立演练和教学案例不会插入正式评估或隐患数据。环境空值保持未知，`0` 风速保持 `0 m/s`。报告导出使用已应用的配置快照，修改草稿后必须重新应用才更新演示和导出内容。

## 2. 使用方法

1. 打开本地平台并进入管理页面，点击顶部“铁路数字站场”；已有评估也可直接点击其“情景演示”。
2. 选择来源记录或“教学案例”，点击“带入并预览”。核对右侧来源快照和照片。
3. 选择地区模板、问题对象和定性情景，填写问题、原因及措施。需要时上传照片并标注。确认映射后点击“确认配置并进入演示”。
4. 使用右侧阶段按钮或时间轴定位过程；可播放、暂停、重播和切换倍速。
5. 进入“参数与评估资料”，核对快照后下载 Word、Excel 或配置 JSON；绑定记录时可返回来源报告。
6. 下次打开可点击“恢复本会话配置”。关闭浏览器会话可能丢失会话存储，需长期留存时下载配置 JSON。

当前业务记录带入入口针对有风险评估页面权限的账号，使用平台已加载且可访问的记录。没有权限或记录为空时提供独立演练和教学案例，不通过场景入口扩大业务数据权限。

## 3. 代码与数据边界

- `daima/src/railScenario.ts`：来源适配、配置类型、导入校验、字段约束、阶段说明与报告数据。
- `daima/src/RailScenarioWorkspace.tsx` / `.css`：配置、来源预览、照片标注、播放控制、资料页、会话保存和响应式布局。
- `daima/src/sceneExport.ts`：利用已有 `fflate` 生成标准 Office Open XML 包；Excel 内容写为文本，报告文字进行 XML 转义。
- `daima/src/SimulationSwitch.tsx`：弹层入口、焦点与背景交互管理，原页面滚动恢复；与评估列表的事件连接。
- `daima/src/App.tsx` / `SafetyAssessmentPanel.tsx`：提供授权范围内记录，增加演示入口和返回来源详情。
- `daima/src-df/85-scenario.js`：定性事故动画、对象位置映射、阶段与时间轴；消息须来自当前父窗口且同源。原教学风险、隐患数据不被该模块写入。
- `daima/build-df.js`：包含新场景分片，同步生成根目录与 public 的单文件；生产构建再复制到 dist。

本轮没有新增或变更后端 API、数据库表、用户角色、正式评估算法或整改流转规则。配置和照片仅在当前浏览器处理和会话留存，不上传到外部 AI 服务。会话草稿不是数据库归档，也不提供跨设备同步。

## 4. 验证证据

### 命令与文件验证

- `npm run build`：通过，包括离线场景、TypeScript 与 Vite 构建。保留既有主应用代码块体积、`inspection.ts` 混合静态/动态导入提示。
- `npm run lint -- src`：通过，无警告。
- `node qa-df/railway-contract.cjs`：通过，原六地区布局、净空、列车、人员巡检、统计与离线一致性回归。
- `node qa-df/scenario-contract.cjs`：通过。覆盖源记录不变、映射确认、导入校验、照片输入边界、未知与零值区分、XML 转义和 Office 包结构，以及六地区 × 三对象 × 三情景的阶段、特效分支、播放、暂停、终点停止、变换有限值、业务统计不变和消息来源限制。
- 通过 Python `zipfile`/XML 解析器、`python-docx`、`openpyxl` 读取测试产物及浏览器实际下载的文件；Word 段落、Excel 两张工作表可读，`0 m/s` 未变成未知。带照片的 Word 含一个嵌入图像和归一化标注文字。

Office 文件完成结构与库读取验证；本轮未在 Microsoft Word/Excel 桌面端逐页检查排版，也未验证所有 Office 软件版本。

### 浏览器验证

在本地 `http://127.0.0.1:5173/#/` 的安全管理员演示账号中检查：

- 空配置禁止进入演示，明确列出名称、问题和映射缺失项；教学案例可完成应用。

- 下载 `.docx`、`.xlsx`、JSON 成功；温度未知、风速零值和原记录状态在资料中正确区分。
- 创建一条明确命名为“联动验收合成记录（测试后清理）”的本地演示记录，通过列表入口带入原编号、问题、等级、照片和措施；从场景返回后打开同一条来源报告，原等级、状态保持。测试记录随后已清理，评估列表恢复零条；没有写入生产数据库。

## 5. 未纳入本轮的范围

1. **闭环流程替换：** 需求2与原双人确认存在差异。依整理文档的待确认规则，本轮沿用现有流程，未擅自改变最终确认顺序。
2. **AI 图片分析、图片自动建模、在线 Agent 生成模型：** 尚未接入；当前是代码预制模板加人工配置，不冒充在线生成。
3. **定量后果及经济损失：** 未计算超压、热辐射、伤害半径或损失金额；特效尺寸是视觉表现，不是安全距离。
4. **专属场站与商业服务：** 没有新增付费、订单或定制建模交付功能；六地区仍是示范模板。
5. **云端归档、真实数据库联调与上线：** 当前新增链路为本地前端实现，未验证真实业务账号、生产权限和实际场站资料；会话配置也未接入数据库。

后续若启用上述能力，需分别落实业务规则、真实资料、模型及校核标准、存储接口和验收范围。当前版本可用于完整演示“数据带入—模板配置—问题过程—资料导出”，不能作为真实事故后果计算系统。
