# 铁路站场底部索引与侧栏可视化

更新日期：2026-11-18。

## 展示与操作

- 中间保留铁路站场、列车通行和四名安全人员巡检。
- 六个作业分区索引移到场景下方，工具栏上方；点击索引可定位并查看作业点详情。
- 左侧显示原风险等级环图、四色数量及比例、风险评估问题、检测值与标准、来源评估入口。
- 右侧显示闭环率环图、未闭环/复核中/已闭环数量、平均闭环耗时、逾期项、六阶段梯形分布及综合整改措施。
- 原措施按去除首尾空白后的完整文字分组；点击展开可查看关联记录及来源入口，不生成新的处置指令。
- 延续蓝黑科技配色与微软雅黑。侧栏独立滚动；900px 以下采用互斥抽屉，底部索引可横向滚动。

## 数据口径

平台入口：管理平台 → 铁路数字站场 → 浏览六地区站场。工作区提供当前账号可访问的评估快照，不读取其他账号的数据、不回写原记录。

| 指标 | 口径 |
| --- | --- |
| 风险等级 | 所有授权评估的原等级，包含已闭环历史，整改不会自动改级 |
| 风险评估问题 | 原评估的问题说明、危险源、检测值和标准；未识别隐患的评估也保留 |
| 隐患分母 | `hasHazard` 为真的评估记录 |
| 已闭环 | 当前状态为“已闭环”或兼容状态“已整改” |
| 闭环率 | 已闭环数 / 全部隐患数；无隐患时显示“—” |
| 治理阶段 | 待整改、整改中、待复核、复核中、待经理确认、已闭环六种互斥当前存量；未知状态另行提示，不冒充累计转化漏斗 |
| 平均闭环耗时 | 原记录创建时间至最后一次有效闭环推进日志的时间均值，标明有效样本数；排除缺失、无效、负时长及已重新打开的记录，保留零时长 |
| 逾期项 | 当前快照没有期限字段，平台模式显示“未知” |

独立预览和离线文件明确显示教学数据；教学已闭环数量来自原地区教学汇总，没有逐项闭环时间，不计算平均耗时。空的平台快照保持为空，不回退到教学数据。

## 修改与验证

源文件为 `daima/src-df/shell.html`、`dashboard.css`、`58-dashboard-model.js`、`60-data.js`。`railScenario.ts` 从原日志提取闭环时间，`railHazardModel.ts` 传递检测标准和时间字段。`build-df.js` 同步生成网页与离线文件。

本轮已通过：

- `node qa-df/dashboard-contract.cjs`：原等级、阶段及分母、空值/未知/零值、耗时覆盖率、措施分组、源记录不可变及有效闭环日志选择。
- `node qa-df/railway-contract.cjs`：六地区几何、铁路净空、列车和巡检动画、产物一致性与脚本语法。
- `node qa-df/scenario-contract.cjs`：原平台空状态隔离、风险与治理统计、情景条件及消息边界等既有回归。
- `npm run lint -- src`、`npm run build`。
- 浏览器检查：平台演示账号无评估时显示原平台空数据；独立教学场景在 1280×720、1440×900 与 390×844 下展示，未出现页面横向溢出；手机底部索引可滚动，抽屉可切换，措施可展开，索引可定位应急保障区。
- 前端 5173 与后端健康接口返回 200，健康接口报告数据库已连接。

截图：`daima/qa-df/results/railway-dashboard-bottom-index.jpg`、`railway-dashboard-mobile.jpg`。截图中的非零统计是明确标识的教学数据。真实业务非空账号的端到端来源跳转及闭环日志展示尚未实测；统计逻辑使用合成算例验证，未向业务库写入测试记录。

构建仍存在原有大包与静态/动态重复导入提示，不影响本轮构建通过。本轮未部署到外网。
